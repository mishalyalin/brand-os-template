How to use the Brand OS

Three ways to query the Marketing Brain depending on what you are doing.

1. Browser (you are here)

For one-off lookups, brand-book reading, and pre-meeting prep. The search box on the front page accepts plain English, plain Russian, or any mix.

Example queries that work:

  • founder pratfall for cart abandon
  • anchoring on PDP
  • salt on watermelon sweet pairing
  • labour illusion for ingredient sourcing
  • loss aversion welcome email

Direct links also work:

  • /for-vector/bodybuilder - everything for one of the 6 content vectors
  • /for-stage/hero_landing - everything tagged for a funnel stage
  • /tactic/pratfall_effect - everything tagged with a tactic
  • /canon?school=voss - filter canon principles by school
  • /icp - the canonical ICP and 6 content vectors
  • /guidelines - the 4 canonical foundation files

2. Claude session

For drafting customer copy, generating email sequences, building landing pages, or any task where the answer becomes shipped text.

Clone the repo into your working directory and open Claude Code in it:

git clone git@github.com:YOUR-ORG/YOUR-BRAND-OS-REPO.git
cd YOUR-BRAND-OS-REPO
python3 tools/marketing_brain.py stats
claude

The repo's CLAUDE.md auto-loads as the system prompt and tells Claude:

  • To query the Brain before generating any customer-facing copy.
  • The seven hard rules (short hyphens, no emojis, no exclamation marks, no medicine vocabulary, no category comparisons, no fabricated claims, no consultancy jargon).
  • The names policy from `00-foundations/founder-stories.md` - founder names, on-camera policy.
  • The four-layer Brain architecture so Claude knows what to cite.

The simplest prompt that works:

Use the Marketing Brain to find a tactic for <your task>. Draft the copy. Run the Wall-1 and Wall-2 hygiene scan. Cite primary sources.

3. Building a customer-facing site or landing page

If you are working with a designer, developer, or agency on a new page:

  1. Send them this URL plus credentials. They read the brand guidelines and the ICP page before drafting.
  2. For each content block, query the Brain. "What tactic should the hero stack? What cocktail fits the cart-abandon email?"
  3. Stack from the top down. Layer 0 (positioning) is the strategic frame. Layer 1 (cocktails) is the recommended stack. Layer 1.5 (canon) is the principles inside the stack. Layer 2 (Vault rows) is the evidence.
  4. Apply the Wall-1 and Wall-2 hygiene check before shipping. Hygiene chips appear on every retrieved card. If a card has a hygiene flag, the tactic still works but the wording around it needs to stay culinary and within-customer rather than medicinal or category-comparative.
  5. Cite primary sources. The Brain returns the primary source (Kahneman, Voss, Cialdini, Bohner, etc.) for every retrieved item. The Brand OS itself is internal. Customer copy cites the underlying work.

What the Brain will not do

  • It will not fabricate studies. If the corpus does not cover your question, you get a no-match notice and an instruction to gather evidence first.
  • It will not invent customer numbers, prices, or claims that are not traceable.
  • It will not contradict the canonical files. If you see drift, the canonical files in the repo win and the web interface is stale - file a PR to fix.

Access and credentials

This interface is internal. Do not share the URL or basic-auth credentials outside the founding team. The site is intentionally not indexed (noindex, nofollow, noarchive) and is behind an unguessable subdomain and basic auth.

To add a teammate: ask Misha directly. Do not paste credentials into Slack, Notion, or email.

Edit workflow

  1. Edit the canon file in the repo (Markdown for content, JSON for vocab).
  2. Open a PR on your fork of this Brand OS repo.
  3. CI runs the Brand Voice Check, Claims Trace, and the auto-merge tier decision.
  4. Once merged, the deploy hook rebuilds the Brain index on the VPS and the web interface picks up the change within seconds.

The simplest edit - adding a new tactic alias - is a single line in 08-templates/vocab/tactics.json, editable straight from the GitHub UI in your browser.
